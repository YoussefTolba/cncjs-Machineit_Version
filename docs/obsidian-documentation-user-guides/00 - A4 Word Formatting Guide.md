# A4 Word Formatting Guide

Use this page setup when moving these Obsidian notes into Microsoft Word.

## Page Setup

| Setting | Value |
| --- | --- |
| Paper size | A4 |
| Width | 210 mm |
| Height | 297 mm |
| Orientation | Portrait |
| Top margin | 20 mm |
| Bottom margin | 20 mm |
| Left margin | 20 mm |
| Right margin | 20 mm |
| Header from top | 12.5 mm |
| Footer from bottom | 12.5 mm |

## Recommended Word Styles

| Style | Font | Size | Spacing |
| --- | --- | --- | --- |
| Normal | Calibri | 11 pt | 0 pt before, 6 pt after, 1.15 line spacing |
| Title | Calibri Bold | 24 pt | 0 pt before, 12 pt after |
| Heading 1 | Calibri Bold | 16 pt | 18 pt before, 10 pt after |
| Heading 2 | Calibri Bold | 13 pt | 14 pt before, 7 pt after |
| Heading 3 | Calibri Bold | 12 pt | 10 pt before, 5 pt after |
| Code block | Consolas | 9.5 pt | Single spacing |
| Table text | Calibri | 10.5 pt | 0 pt before, 3 pt after |

## Word Import Method

1. Open a blank Word document.
2. Set paper size to A4.
3. Set all margins to 20 mm.
4. Create or update the Word styles listed above.
5. Copy one Obsidian note at a time into Word.
6. Apply Word heading styles to headings if Word does not import them automatically.
7. Keep each major guide starting on a new page.
8. After pasting tables, set table width to fit the page.
9. Use page breaks before large sections instead of adding many blank lines.

## Layout Rules For Clean Word Output

- Keep one idea per paragraph.
- Keep procedure steps short.
- Avoid very wide tables.
- Avoid screenshots unless they are needed.
- Put long G-code examples in code blocks.
- Use page breaks between major guides.
- Do not split a warning from the steps it belongs to.
- Keep headings with the next paragraph when possible.

## Suggested Document Order

1. Cover page.
2. Startup guide.
3. Full user manual.
4. Probing direction guide.
5. Homing and jogging guide.
6. First project checklist.
7. Troubleshooting appendix.
